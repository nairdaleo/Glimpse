# First runnable app implementation plan

> **For agentic workers:** Use focused implementation tasks with independent review. The owner authorized coding and subagents on 2026-11-13. Work in disjoint source directories; the coordinator owns integration and commits.

**Goal:** A runnable native menu-bar monitor with configurable three-column icon, live detail panel and optional bandwidth readout.

**Architecture:** A dependency-free Swift package separates pure metric/settings logic, native system readers, and the AppKit/SwiftUI application. One background scheduler publishes snapshots to the main-thread interface. A script bundles the executable into a development .app.

**Tech stack:** Swift 5 language mode, SwiftPM tools 5.9+, AppKit, SwiftUI, Darwin/Mach, IOKit, SystemConfiguration.

**Spec:** [../../design.md](../../design.md). The owner approved proceeding; remaining proposed visual defaults can be refined after running the app.

## Global constraints

- MIT; independent implementation, no GPL source imports.
- macOS 12 deployment target, native Intel and Apple silicon build verification.
- One compact icon; clicking opens detailed live status. Numeric blocks optional.
- Native background sampling, monotonic elapsed time, per-interface baselines, unavailable is not zero.
- No account, telemetry, privileged helper, external package, or persistent metric history.

## Shared interfaces

The following public types belong to GlimpseCore. Names form the integration contract.

- `MetricID: String, Codable, CaseIterable, Identifiable`: cpu, memory, download, upload, battery, disk, thermal; `title: String`; id = rawValue.
- `MetricReading`: `value: Double?`, `detail: String`, `timestamp: TimeInterval`; public init with those labels. Values are percentages for CPU/memory/battery/disk, bytes/second for network, thermal ordinal 0...3.
- `Snapshot`: `timestamp: TimeInterval`, `readings: [MetricID: MetricReading]`, `networkInterface: String`, `availableInterfaces: [String]`; public init with those labels and default empty collections/string.
- `MeterColour: String, Codable, CaseIterable, Identifiable`: mint, blue, purple, orange, pink; title and id.
- `ThresholdDirection: String, Codable, CaseIterable`: above, below.
- `ColumnConfiguration: Codable`: metric, colour, warningThreshold: Double?, criticalThreshold: Double?, thresholdDirection. Public init defaults optional thresholds to nil and direction above.
- `AppSettings: Codable`: columns: [ColumnConfiguration], showBandwidth: Bool, bandwidthInBits: Bool, networkInterface: String? (nil = automatic), networkCeiling: Double (bytes/s), refreshInterval: Double, monochrome: Bool. `init()` provides three columns CPU/memory/download, no bandwidth block, 12_500_000 B/s ceiling, one-second refresh. `validated() -> AppSettings` repairs invalid/missing data. Partial Codable documents decode with defaults.
- `MetricPresentation.formatted(value: Double?, metric: MetricID, bits: Bool = false) -> String`; `normalized(value: Double?, metric: MetricID, networkCeiling: Double) -> Double?` clamped 0...1, nonfinite unavailable.
- `HistoryPoint`: timestamp: TimeInterval, value: Double?; public init.
- `MetricHistory`: `init()`, `samples: [MetricID: [HistoryPoint]]` read-only externally, mutating append(_ snapshot: Snapshot); bounded to five minutes and at most 600 samples per metric, no duplicate timestamps per reading, preserve nil gaps.

GlimpseMonitor produces `NativeSampler.init()`, `sample(settings: AppSettings, detailVisible: Bool) -> Snapshot`, `resetBaselines()`. Its mutable state is confined to the coordinator's serial queue. It uses the types above, never AppKit/SwiftUI. Native reader helpers can remain internal and testable with @testable import.

## Review focus

1. Startup, failed reads and sleep/wake never create fabricated traffic spikes.
2. Interface changes and VPN coexistence do not combine duplicate physical/tunnel traffic.
3. Invalid settings cannot create division by zero or an unbounded timer/history.
4. Clicking/reopening/keyboard dismissal works while samples continue; UI writes stay on the main thread.
5. Build script produces a launchable .app, and architecture/deployment metadata matches the stated scope.
